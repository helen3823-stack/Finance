# 주가 방향 예측

당일 **장 시작(09:30) 직전까지** 쓸 수 있는 데이터만으로,
그날 종가가 전일 종가보다 올랐는지 맞히는 문제임.

| label | 구간 | 실측 비율 (기준일 구간) |
|---|---|---:|
| 0 급하락 | −2.5% 미만 | 7.4% |
| 1 하락 | −2.5% ~ −0.6% | 24.1% |
| 2 보합 | −0.6% ~ +0.6% | 32.9% |
| 3 상승 | +0.6% ~ +2.5% | 27.4% |
| 4 급상승 | +2.5% 초과 | 8.3% |

## 시작

```bash
uv sync                                       # 가상환경과 패키지. uv.lock 이 생김

uv run python main.py check   --split 2026-06-01    # 출력 규격 검사
uv run python main.py eval    --split 2026-06-01    # 점수
uv run python main.py predict --date  2026-09-10    # 하루 예측
```

`uv sync` 가 만든 `uv.lock` 을 팀 저장소에 함께 올리면 팀원 간 버전이 맞음.
torch 가 들어 있어 첫 설치는 오래 걸림.

`--split` 앞이 학습, 그날부터가 평가임. `predict --date` 는 기준일이고 그 다음 거래일을
예측함. 마지막 거래일(2026-09-14)은 다음 날이 없어 기준일로 못 씀.
`example/1_eda.ipynb` 로 데이터를 둘러보고, `2_modeling.ipynb` 로 모델을 만듦.

## 지켜야 할 것

두 개뿐임. 나머지는 자유임.

```python
# src/model.py
def load_model(): ...            # 학습을 마친 모델을 돌려줌
class Model:
    def predict(self, day): ...  # symbol / label
```

학습 방법이나 위치에는 제약이 없음. 결과를 저장해 두고 `load_model()` 에서
읽어오기만 하면 됨. 채점할 때는 학습을 다시 돌리지 않음.

완성된 예시가 `example/sample_model.py` 에 있음. 그대로 옮겨 써도 됨.

### 출력 규격

| 규칙 | |
|---|---|
| column | `symbol` / `label` 두 개 |
| label | `0` ~ `4` 만. 실수·NaN·문자열 안 됨 |
| 종목 | `day.symbols` 를 **빠짐없이, 그것만** |
| 중복 | 같은 종목 두 번 안 됨 |

DataFrame 이든 dict 리스트든 받음. 어기면 거기서 바로 멈춤.

```
predict 결과가 규격에 안 맞음
  0행 {'symbol': 'ADI', 'label': 7} -> label: 0(급하락)/1(하락)/2(보합)/3(상승)/4(급상승) 중 하나여야 함. 받은 값: 7
```

`python main.py check` 로 제출 전에 확인하면 됨.
통과시켜 두면 채점 도중에 멈출 일이 없음.

## 데이터

```python
from src import Dataset

ds = Dataset()
train, test = ds.split("2026-06-01")

day = test[0]
day.date        # 기준일
day.target      # 예측 대상일 (다음 거래일)
day.cutoff      # 대상일 09:30. 여기서 모든 데이터가 잘림

day.daily(days=20)                      # 최근 20거래일 일봉
day.price(days=1)                       # 시간봉
day.news(days=1)                        # 기사
day.news(["AMD"], days=5, with_text=True)
day.earnings(days=90)
day.analyst(days=30)
day.reddit("stocks", "comments", days=1)

day.symbols     # 예측 대상 종목
day.y           # 정답 (학습할 때만)
```

`day.date` 는 기준일, `day.target` 은 그 다음 거래일임. 기준일 장 마감 후 나온 뉴스와
대상일 개장 전 시간외 거래까지 들어옴. 금요일을 기준일로 잡으면 주말 뉴스가 전부 들어옴.

`days` 는 **거래일** 기준이고 기준일을 포함해서 셈. 시각 단위가 필요하면 `hours`,
날짜를 직접 정하려면 `since` 를 씀. 대상일 개장 전 움직임만 보려면 `hours=20` 정도가 맞음.
`days=1` 은 기준일 00:00 부터라 기준일의 pre 세션까지 섞임.

필요한 것만 골라 한 번에 받을 수도 있음.

```python
x = day.load(days=5, symbols=["AMD", "MSFT"],
             news=True, earnings=True, reddit=["stocks", "investing"])

x["daily"], x["price"], x["news"], x["reddit"]["stocks"]
```

며칠을 볼지는 각자 정하면 됨. 구간을 아무리 넓혀도 끝은 항상 `cutoff` 라
과거 방향으로만 늘어남.

| 표 | 내용 |
|---|---|
| `daily` | 일봉. 전일 종가와 수익률 포함 |
| `price` | 1시간봉. 정규장 + 시간외(pre/post) |
| `news` | 기사 제목·논조·본문. 2024-08-13 부터 |
| `earnings` | 실적 발표. EPS 예상·실제·서프라이즈. 2020년부터 |
| `analyst` | 목표주가, 등급 변경. 2012년부터 |
| `reddit` | 글·댓글. `score`, `n_comments` 는 36시간 뒤 값이라 쓰지 말 것 |

50종목. 기준일은 **2024-08-13 ~ 2026-09-11** 임. 표마다 시작이 달라서(일봉·시간봉 2023-10,
Reddit 2024-01, 뉴스 2024-08-13) 모든 표가 갖춰진 날부터만 기준일로 씀. 그 앞의 일봉·시간봉은
`day.daily(days=120)` 처럼 과거로 거슬러 볼 때만 쓰임.

## 미래를 보지 않음

이 문제의 핵심임. **`day` 에서 꺼내는 데이터는 전부 `cutoff` 에서 잘림.**

자르는 기준이 `known_at` 인데, **언제 일어났나**가 아니라
**언제 알 수 있었나**임. 둘은 다름.

| 데이터 | 일어난 시각 | 알 수 있게 된 시각 |
|---|---|---|
| 1시간봉 | 봉의 **시작** (09:30) | 봉이 닫히는 10:30 |
| 일봉 | 그날 | 16:00 마감 |
| Reddit 글·댓글 | 올라온 때 (`created_et`) | 올라온 직후. 이 시각으로 자름 |
| Reddit `score` / `n_comments` | 글이 올라온 때 | **36시간 뒤** (2차 수집값) |

1시간봉이 함정임. 09:30 봉은 09:30\~10:30 구간이라 10:30 이 돼야 채워짐.
시작 시각으로 자르면 09:30 에 그 봉을 이미 아는 셈이 됨.

Reddit 만 예외로 `known_at` 열이 없고 `created_et`(올라온 시각)로 자름. 글과 댓글 본문은
올라온 직후 수집되어 09:30 에 볼 수 있는 정보가 맞음. 하지만 `score` 와 `n_comments` 는
36시간 뒤에 다시 긁은 값이라 **cutoff 시점에는 알 수 없는 미래 정보**임. 인기 글을
고르는 데 쓰면 미래를 보는 셈이니 feature 로 쓰지 말 것.

정답(`day.y`)은 `known_at` 이 16:00 이라 장중 데이터에는 안 섞임.
`predict` 안에서 `day.y` 를 쓰면 반칙임.

## 평가

**주 지표는 `score`** 임. 다섯 등급에 순서가 있으므로, 얼마나 멀리 틀렸는지를
가중치로 반영함.

```
score = 1 - Σ w·O / Σ w·E
```

`O` 는 실제 혼동행렬, `E` 는 같은 분포에서 무작위로 찍었을 때의 기대치임.
우연으로 맞은 몫을 빼기 때문에 **0 이 기준선**이 됨.

```
+1    전부 맞힘
 0    정보가 없는 것과 같음
음수   우연보다 못함
```

한 클래스만 계속 찍으면 정확히 0 이 나옴. 전부 보합이든 전부 급상승이든
마찬가지라 한쪽으로 몰아 찍어서는 점수가 오르지 않음.

### 가중치

```
w[i][j] = (i - j)² × (|i - 2|)²        행 i = 정답, 열 j = 예측
```

| 정답 \ 예측 | 급하락 | 하락 | 보합 | 상승 | 급상승 |
|---|---:|---:|---:|---:|---:|
| **급하락** | 0 | 4 | 16 | 36 | **64** |
| **하락** | 1 | 0 | 1 | 4 | 9 |
| **보합** | 0 | 0 | 0 | 0 | 0 |
| **상승** | 9 | 4 | 1 | 0 | 1 |
| **급상승** | **64** | 36 | 16 | 4 | 0 |

세 가지가 들어 있음.

- **급등락을 맞히는 게 가치가 큼** — 정답이 급등락인 행은 가중이 4배임.
  급등락을 놓치면 하락·상승을 놓칠 때보다 네 배 깎임.
- **보합은 가치가 적음** — 정답이 보합인 행은 전부 0 이라 점수에 영향이 없음.
- **반대로 찍으면 크게 깎임** — 거리 제곱이라 멀수록 급격히 커짐.
  급하락↔급상승이 64 로 가장 큼.

### 실제로 재 보면

| | score | 정확도 |
|---|---:|---:|
| 전부 보합 | 0.000 | 0.329 |
| 전부 급상승 | 0.000 | 0.082 |
| 무작위 | -0.007 | 0.201 |
| 방향만 맞고 세기는 틀림 | +0.834 | 0.844 |
| 급등락만 잡고 나머지 보합 | +0.862 | 0.485 |
| 급등락을 정반대로 (나머지 보합) | -1.818 | 0.329 |
| label 을 전부 맞힘 | +1.000 | 1.000 |

정확도가 0.844 인 쪽보다 0.485 인 쪽이 점수가 높음.
급등락을 잡아내는 것이 자잘하게 여러 번 맞히는 것보다 가치가 크기 때문임.
**정확도만 보면 판단을 그르침.**

가중이 비대칭이라 아주 나쁜 예측은 −1 아래로 내려갈 수 있음.

가중치가 `(i-j)²` 만인 보통의 QWK(quadratic weighted kappa)와는 다름. sklearn 의
`cohen_kappa_score(weights="quadratic")` 와 값이 일치하지 않으니 비교하지 말 것.

### 함께 보는 값

| | 뜻 |
|---|---|
| `accuracy` | 맞힌 비율 |
| `direction` | 방향 적중률. 보합을 뺀 나머지에서 오르내림만 봄 |
| `big_recall` | 실제 급등락 중 급등락으로 맞힌 비율 |
| `big_prec` | 급등락으로 예측한 것 중 실제로 급등락이던 비율 |

`big_recall` 과 `big_prec` 은 같이 봐야 함. 급등락을 남발하면 포착은 오르지만
적중이 떨어지고, 반대로 찍힌 만큼 크게 깎임.

### 채점

- 제출물은 **`src/model.py` 와 `artifacts/`** 임. 나머지 `src/` 와 `main.py` 는
  채점자가 원본으로 덮어쓰므로 거기를 고쳐도 반영되지 않음.
- 평가 구간은 **배포하지 않은 이후 날짜**임.
- 종목은 **배포한 50개 중 10개 + 처음 보는 10개**임.
  특정 종목에 맞춰 외운 게 아니라 처음 보는 회사에도 되는지 봄.
  새 종목도 일봉·시간봉 과거는 같은 길이로 제공됨.
- 채점자는 같은 `main.py` 를 다른 데이터로 돌림.
  종목 이름이나 날짜를 코드에 박으면 안 됨.
- `day.symbols` 가 그날 채워야 하는 종목임. 개수는 달라질 수 있음.
- `load_model()` 은 `artifacts/` 만 읽어야 함. 채점 환경에는 `dataset/` 외의 파일이 없음.

## 교차검증

`ds.split(날짜)` 하나로 만들면 됨. 노트북 2절에 세 가지가 있음.

```python
train, test = ds.split("2026-06-01")          # holdout
for on in ["2026-03-01", "2026-05-01"]:       # walk-forward
    train, test = ds.split(on)
train = train[-120:]                           # rolling — 최근 구간만
```

과거로 미래를 예측하는 순서만 지키면 방식은 자유임.
무작위로 섞으면 내일 데이터로 오늘을 학습하는 꼴이 됨.
